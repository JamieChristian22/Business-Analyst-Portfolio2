# Community practice tasks — business and systems analysis

These activities help newcomers learn requirements, traceability and process mapping while providing clear, **small opportunities to improve documentation**. This portfolio includes independent exercises and simulated outcomes. It is not a collection of client-approved, automatically redistributable business templates.

Start with the [portfolio overview](README.md), [reviewer guide](REVIEWER_GUIDE.md), and [contributing instructions](CONTRIBUTING.md). The tasks are **free**, optional and not paid bounties.

## Task 1 — Trace one requirement to acceptance

1. Inspect [Requirements Documentation Examples](<Requirement Documentation Examples>) and [Requirements Planning Artifacts](<Requirements Planning Artifacts>).
2. Select one illustrative functional requirement.
3. Draft a brief *original* practice trace: requirement → acceptance criterion → UAT scenario → expected result.
4. If the original resource does not clearly connect these steps, open a documentation issue describing the gap, or propose a small clarifying example with permission to redistribute it.

**Done when:** the trace is understandable, uses fictional or authorized data, and avoids claiming that a real client accepted the requirement.

## Task 2 — Explain one as-is to to-be process

1. Review [Business Analyst Models and Diagrams](<Business Analyst Models and Diagrams>).
2. Identify one decision point and the problem it illustrates.
3. Write two or three sentences describing a possible *to-be* improvement and one measurable success criterion.
4. If a diagram lacks a legend or uses an unclear label, propose a focused accessibility/documentation improvement.

**Done when:** a first-time reader can connect process symbols to the business question without changing original project evidence.

## Task 3 — Make a resource easier to use

Review [README.md](README.md) and [REVIEWER_GUIDE.md](REVIEWER_GUIDE.md). Find one broken link, missing explanation, accessibility issue, or claim whose simulated status is unclear.

**Done when:** the proposed fix identifies the file/section, includes a concrete improvement, and documents what was verified. Do not replace licensed or third-party media without source-rights verification.

## Contribute responsibly

Use the [documentation report or improvement proposal templates](https://github.com/JamieChristian22/Business-Analyst-Portfolio2/issues/new/choose). Check existing issues and PRs first. Keep the scope reviewable, avoid proprietary materials or private client information, and follow [CONTRIBUTING.md](CONTRIBUTING.md).

**Funding distinction:** these are learning and voluntary contribution ideas. They are not promised paid work; separately commissioned work needs an explicit, verifiable fee and written terms. [GitHub Sponsors](https://github.com/sponsors/JamieChristian22) is optional.
